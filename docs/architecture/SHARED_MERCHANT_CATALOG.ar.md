# لوحة التاجر والكتالوج المشترك — 29 أكتوبر 2026

## التصحيح بعد تجربة الإنتاج

كانت قائمة الاختيار تقرأ `catalogProducts` الجديدة فقط، بينما المنتجات الموجودة في `products`؛ لذلك ظهرت فارغة. لم يكن هذا عطل اتصال. القائمة الآن تقرأ التعريفات المشتركة والمنتجات القائمة المنشورة (`inStock == true` وغير المؤرشفة)، وتتيح بحثًا خادميًا ببداية الاسم. لا يلزم اعتماد كل منتج يدويًا قبل أن يراه التاجر.

القراءة لا تنشئ بيانات. عند الاختيار، تنشئ المعاملة تعريفًا مشتركًا للمنتج المنشور إذا لم يكن موجودًا، ثم تربط عرض التاجر به. تُحفظ أسعار وعروض المصدر كما هي. المنتجات المنشورة ذات الوصف الاختياري أو غير المسندة إلى متجر يمكن اختيارها أيضًا. المنتجات غير المنشورة لا تصبح عامة بهذا المسار.

## الأقسام التسعة وروابطها

| القسم | الرابط | البيانات والعمليات الحالية |
| --- | --- | --- |
| الرئيسية | `/merchant/dashboard` | حالة المتجر، ملخص الطلبات المحملة وأحدثها؛ لا يُدّعى أنها إجمالي كل التاريخ |
| الطلبات | `/merchant/orders` | التذاكر الحية والتحضير، والسجل الذي تحمله الواجهة؛ التتبع شاشة داخلية `/merchant/tracking` |
| المنتجات | `/merchant/products` | منتجات المتجر واختيار منتج قائم من سنجوب، السعر والتوفر والبحث والتصنيفات والصفحات |
| المخزون | `/merchant/inventory` | التوفر والأرشفة والاستعادة؛ لا توجد كميات فعلية أو دفتر حركات مخزون |
| العملاء | `/merchant/customers` | أسماء ومراجع الطلبات المرتبطة بالمتجر من أول 100 طلب محمل؛ دون هواتف أو معرفات حسابات أو قراءة `users`؛ للمدير فقط |
| التقارير | `/merchant/reports` | حسابات تقديرية للطلبات المحملة، مع فصلها بوضوح عن التسويات والتحويلات الفعلية |
| المدفوعات | `/merchant/payments` | قراءة مقيدة بالمتجر من `merchantSettlements` مع صفحات؛ للمدير فقط؛ المرجع المسجل ليس إثبات تنفيذ تحويل بنكي |
| الإعدادات | `/merchant/settings` | بيانات النشاط والرسوم المسجلة وتغيير حالة الإتاحة للمدير؛ تعديل العنوان والرسوم وساعات العمل والصلاحيات يظل عبر الإدارة |
| الدعم | `/merchant/support` | إرشادات الاستخدام ورابط دعم سنجوب؛ نظام التذاكر غير متاح حاليًا |

تعمل روابط الأقسام مباشرة بعد تسجيل الدخول، وتتوافق مع الرجوع/التقدم في المتصفح. الأقسام ظاهرة في التنقل، مع حالات تحميل وخطأ وسجلات فارغة واضحة، دون اختلاق عملاء أو أرصدة.

## نموذج البيانات ومنع التكرار

- `catalogProducts/{catalogProductId}`: تعريف مشترك للاسم والوصف والتصنيف والصورة والخيارات، دون سعر متجر أو عقده أو بيانات عملائه. التعريف ثابت في هذه النسخة؛ محرر عام لتحديث التعريفات ليس ضمنها.
- `catalogOffers/{sha256(storeId + NUL + catalogProductId)}`: علاقة فريدة تربط المتجر والمنتج العام بمعرف عرضه.
- `products/{productId}`: عرض المتجر المنشور، بسعره وتوفره وأرشفته و`catalogProductId`. يحتفظ بإسقاط حقول التعريف لتوافق الويب والموبايل الحاليين؛ ليس تعريفًا آخر يحرره التاجر من اللوحة.
- لقطات بنود الطلب وأسعار الشراء القديمة لا تتغير.

عند اختيار منتج قائم للمتجر نفسه، يُستخدم سجله الأصلي تلقائيًا. يمكن أيضًا اختيار «ربط بسجل قائم في متجري» لسجل قديم مطابق، مع حفظ معرفه وسعره وتوفره. لا ينقل الخادم سجلات متجر آخر، ولا يدمج منتجين متشابهين بالاسم تلقائيًا. اختلاف العبوة والعلامة والخيارات قد يعني اختلاف المنتج.

إذا اختار متجر آخر المنتج المنشور، يُنشأ عرضه هو بسعره، وبحالة غير متاح حتى يفعّله صراحة. إنشاء التعريف وربط المصدر والعرض الجديد ومؤشر منع التكرار تتم في معاملة واحدة. إعادة الضغط أو الطلبات المتزامنة تعيد العرض نفسه.

## القراءة والبحث

الكتالوج العام يقرأ صفحات من 50 سجلًا، وينتقل بعدها إلى المنتجات المنشورة القائمة. البحث بالاسم يجري على الخادم عبر نطاق prefix، وليس ضمن أول صفحة فقط. مؤشرات الصفحات تبين المصدر، وتتحقق الواجهة من نتائج البحث المتأخرة قبل عرضها. عروض التاجر بصفحات من 100 سجل، مع زر تحميل المزيد.

التصنيفات والاسم والخيارات فقط من المصدر العام. لا تُعرض تكلفة المصدر أو سعره أو عقده. الأرشفة تخص عرض المتجر، والاستعادة تعيده غير متاح. الاعتماد الإداري اليدوي يظل متاحًا اختياريًا، لكنه لم يعد شرطًا لقراءة المنتجات المنشورة.

## اختيار المنتجات في الواجهة

زر «إضافة منتج» يفتح نافذة مستقلة بحقل بحث واحد وبطاقات مصورة. تظهر النتائج من أول حرف، وتشمل الكتالوج المشترك والمنتجات المنشورة القائمة في الاستجابة نفسها عندما تسمح الصفحة. تُحمّل الصفحات التالية عند التمرير، مع زر بديل للتحميل اليدوي.

تُعرض الصورة المسجلة في `imageUrl`؛ إن غابت أو فشل تحميلها تظهر حالة «الصورة غير متاحة»، دون استبدالها بصورة لمنتج مختلف. بعد اختيار البطاقة يظهر سعر البيع أسفل النافذة. ربط سجل قديم موجود أصبح خيارًا مطويًا بدل حقل دائم، ولا تتغير حماية المعرفات والأسعار.

صفحة المنتجات لا تعرض بطاقات الإحصاءات العامة أو ترويسة متجر مكررة، وتُخفى مرشحات القائمة حين لا توجد منتجات للمتجر. التصميم يُختبر عند تكبير المتصفح الطبيعي على الموبايل والديسكتوب.

## الوصول والحدود

كل واجهات القراءة الجديدة تمر عبر API الموجود دون إضافة وظيفة Vercel. المتجر من `staff` الموثوقة، لا من معرف يرسله المتصفح. معاملات الربط تفحص المدير والعضوية والتعطيل وإلغاء الجلسة داخل المعاملة. صفحات العملاء والتسويات تعيد فحص العضوية والتحكم بالحساب، وتعيد حقولًا محدودة فقط.

لم يتغير `firestore.rules` وفق قيد العمل الحالي. القواعد القديمة ما زالت تسمح لمدير المتجر ببعض الكتابات المباشرة إلى `products`؛ لذلك ضمان الربط وعدم إنشاء نسخة جديدة هنا يخص مسارات الواجهة وAPI المختبرة، وليس إغلاق كل مسارات SDK القديمة. إحكام ذلك عبر القواعد يحتاج تغييرًا مستقلًا مصرحًا به واختبارات قواعد قبل النشر.

## التحقق

اختبارات الخدمة تغطي كتالوجًا جديدًا فارغًا مع منتجات قديمة موجودة، والبحث، والاختيار المتكرر والمتزامن، والربط بسجل قائم، وعزل أسعار المتاجر، والمنتجات ناقصة الحقول الاختيارية، ونطاق العملاء والتسويات وصلاحيات المدير.

اختبار Chromium يستخدم المكونات الحقيقية بردود API اختبارية، ويفتح الأقسام التسعة على الموبايل والديسكتوب. أُضيفت سيناريوهات الاختيار دون اعتماد يدوي والصفحات الجديدة إلى اختبار Firebase التكاملي ليتحقق منها CI. اختبارات الذاكرة والواجهة لا تثبت ترحيل بيانات الإنتاج أو نجاح نشر Vercel.
