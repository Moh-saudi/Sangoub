# إنشاء الحسابات وتعديلها

## ما تحقق من الكود

إنشاء الحساب في `server/handlers/admin-users.ts` يستخدم كلمة مرور عشوائية قوية من `randomBytes(32)`؛ لم يكن إنشاءً بكلمة مرور فارغة. الخلل في تجربة الإدارة كان عدم توفير رابط تعيين لكل الأدوار وعدم وجود إجراء واضح لإعادة إصداره من قائمة الحسابات. حسابات Google تعتمد الدخول عبر مزود الهوية ولا يلزمها كلمة مرور محلية للدخول عبر Google.

## إنشاء حساب

1. لوحة الإدارة ← سجل المناديب والتجار والمستخدمين ← إضافة قيد جديد.
2. أدخل اسم صاحب الحساب وبريده الحقيقي ونوع الحساب. للتاجر اختر المتجر ومهمة مدير أو تحضير؛ للمندوب أكمل بياناته التشغيلية.
3. اكتب سبب العملية واحفظ. بعد النجاح يغلق نموذج الإنشاء حتى لا يتكرر إنشاء الحساب، وتظهر نافذة تعيين كلمة المرور لكل الأدوار، بما فيها العميل.
4. انسخ رابط التعيين وسلمه لصاحب الحساب عبر قناة خاصة. **النظام يولّد الرابط ولا يرسل بريدًا تلقائيًا من لوحة الإدارة.** صاحب الحساب يفتحه ويختار كلمته؛ الإدارة لا تعرفها ولا تعرضها. Firebase يتحقق من صلاحية الرابط واستخدامه لمرة واحدة.
5. يسجل صاحبه الدخول بالبريد وكلمته ويؤكد بريده عند طلب ذلك. صفحات الدخول: `/courier` للمندوب، `/merchant` للتاجر، `/admin` للإدارة، و`/login` للعميل.

لا يحفظ الرابط في ملف الحساب أو localStorage أو سجل التدقيق؛ يبقى في استجابة الإدارة وذاكرة النافذة حتى إغلاقها. إذا أغلق المدير النافذة قبل نسخه يمكن إصدار رابط جديد من صف الحساب. لا تستخدم بريدًا وهميًا أو كلمة مرور مشتركة للفريق.

## الحسابات الموجودة

من صف الحساب اضغط **تعيين كلمة المرور** لإصدار رابط جديد. لا تحتاج حذف الحساب أو إنشاء UID جديد. يمكن لصاحب الحساب أيضًا استخدام «نسيت كلمة المرور» من شاشة دخوله لإرسال بريد الاستعادة عبر Firebase.

زر **تعديل** يحفظ البيانات؛ لا يغيّر كلمة المرور. تغيير البريد يلغي توثيقه السابق، ويصدر رابط تعيين للبريد الجديد ويتطلب التحقق منه. تغيير الدور/المتجر/المهمة يحفظ الصلاحية الفعلية ويُلغي الجلسات القديمة، مع منع تغيير صلاحية النفس أو إزالة آخر مدير أو تغيير تكليف له طلبات نشطة. تعديل اسم الحساب وحده يبقي التكليف كما هو ويظل ممكنًا مع المهام النشطة.

## حدود التحقق

نجحت فحوص TypeScript والوحدات والخدمات وnative وcompiled API والبناء وفحص 12 مسارًا على الموبايل واللاب توب. أضيفت اختبارات تكامل لإنشاء الرابط واستهلاكه ورفض إعادة استعماله وعدم تخزينه أو تخزين كلمة المرور، ولحفظ الدور والمتجر وحماية الطلبات النشطة. أضيفت تجربة إنشاء الحساب من شاشة الإدارة لاختبار المتصفح المصادق عليه. هذه الاختبارات التي تحتاج Firestore Emulator **لم تنفذ محليًا** بسبب حظر تنزيل المحاكي؛ تتطلب التحقق عبر CI. لا تدّعي هذه الدفعة اختبار إرسال بريد حقيقي أو استهلاك رابط على الإنتاج. لم تتغير قواعد Firestore أو ملفات GPS.
