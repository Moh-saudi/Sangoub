## 1. الخلاصة التنفيذية

- مسارات التطبيق الحالية للمصادقة والبيانات تستخدم Supabase، وملفات الكتالوج والصور تستخدم Cloudflare R2 وفق مسارات الكود والإعدادات الموثقة.
- Flutter يستخدم Supabase Auth. بقي Firebase Cloud Messaging (FCM) قناة نقل للإشعارات.
- أضيف دعم Push للـPWA وربط رمز الويب بحساب Supabase. أضيف أيضًا خيار حملة اختبار تستهدف حساب المدير الحالي.
- تحققت مباشرة من Supabase Production: المشروع نشط، وجداول الإشعارات موجودة وRLS مفعّل عليها، وترحيلا الإشعارات مسجلان.
- لم يثبت تنفيذ تصدير واستيراد تاريخي كامل من Firestore إلى Supabase. أعداد السجلات الموجودة حاليًا لا تثبت مصدرها.
- لم يُنفذ إرسال Push حي إلى هاتف بعد. عدد الرموز المسجلة والحملات والإشعارات في جداول Supabase الثلاثة كان صفرًا عند الفحص.
- نجح بناء الويب الإنتاجي وفحص TypeScript الخاص بالخادم. دفع تحديث PWA إلى GitHub تم؛ حالة نشر Vercel الناتج عنه واختبار الهاتف لم يتم التحقق منهما في هذا التقرير.

## 4. تحقق قاعدة Supabase Production

تم فحص المشروع الحي عبر موصل Supabase للقراءة فقط في 7 نوفمبر 2026. أظهرت النتيجة أن مشروع Sangoub حالته `ACTIVE_HEALTHY` وقاعدة بياناته PostgreSQL 17.

2. `20261106210623` — `notifications_explicit_deny_policies`

### الجداول والأعداد عند وقت الفحص

| الجدول | العدد | ملاحظة |
|---|---:|---|
| `public.profiles` | 4 | عدد ملفات الحسابات في هذا الجدول. |
| `public.stores` | 5 | لا يثبت العدد وحده أن هذه السجلات استوردت من Firebase. |
| `public.products` | 600 | لا يثبت العدد وحده أن هذه السجلات استوردت من Firebase. |

| `public.notification_devices` | 0 | لم يسجل جهاز Push عند الفحص. |
| `public.notification_campaigns` | 0 | لم توجد حملة مسجلة عند الفحص. |

تم تأكيد تفعيل RLS على `notification_devices` و`notification_campaigns` و`notifications`، وكذلك على الجداول الأساسية `profiles` و`stores` و`products` و`orders`. ملفات الترحيل تمنع وصول عميل `anon` أو `authenticated` مباشرة إلى سجلات الأجهزة والحملات؛ يمر الوصول التشغيلي عبر الخادم ذي الصلاحية المناسبة.

### حد مهم في سجل الترحيلات

ملفات SQL أخرى موجودة في المستودع، مثل `supabase/migrations/202610290001_migration_foundation.sql` وملفات `scripts/supabase_*.sql`. لكن سجل ترحيلات Production الذي قرأناه لا يعرض إلا ترحيلي الإشعارات أعلاه. تطبيق SQL يدويًا من SQL Editor قد ينشئ جداول بنجاح من دون تسجيل ذلك كترحيل في `supabase_migrations.schema_migrations`. لذلك وجود الجداول لا يعني أن سجل الترحيلات كامل أو أن تاريخ البيانات القديمة قد استورد.

## 5. تفاصيل تنفيذ الإشعارات

### تخزين البيانات والإرسال

- `public.notification_devices`: رمز FCM المرتبط بمعرّف مستخدم Supabase والمنصة (`android`, `ios`, `web`).
- `public.notification_campaigns`: نص الحملة والجمهور والوجهة ونتيجة الإرسال.
- `public.notifications`: صندوق إشعارات المستخدم وروابط التوجيه.
- الإرسال من الخادم يتم عبر Firebase Admin SDK وFCM؛ بيانات الحملة والجهاز لا تعتمد على Firestore.
- صور الحملات تمر عبر روابط Cloudflare R2.

### دعم PWA

- `src/lib/webPushNotifications.ts` يطلب إذن الإشعارات من المستخدم ويسجل رمز FCM عبر API الخادم.
- `src/sw.ts` يجمع التخزين المؤقت الحالي مع تهيئة Firebase Messaging لاستقبال إشعارات الخلفية والتعامل مع النقر.
- `src/storefront/pages/AccountPage.tsx` يربط زر الإشعارات بإجراء التفعيل أو الإيقاف الفعلي.
- `src/storefront/StorefrontApp.tsx` يعيد مزامنة الرمز عند وجود مستخدم مسجل وإذن متصفح ممنوح.
- `src/components/NotificationCenter.tsx` يتيح خيار «جهازي للاختبار». المقصود حساب المدير الحالي، ولذلك قد يصل الاختبار إلى كل أجهزته المسجلة، وليس إلى تبويب/جهاز واحد مضمونًا.
- إعداد Web Push في الخادم يحدد شعارًا ورابط وجهة ويدعم صورة الحملة عند توفرها.

### ما لم يكتمل بعد

- لم يُسجل هاتف أو PWA كجهاز حتى لحظة فحص قاعدة البيانات.
- لم يُرسل إشعار حي ولم يُختبر وصوله على Android أو iPhone.
- إشعارات أحداث الطلب التلقائية، وجدولة الحملات، ونوافذ العروض المنبثقة ليست جزءًا من التنفيذ الحالي.
- لا توجد نغمة مخصصة. الصوت يتبع إعدادات النظام/المتصفح؛ إضافة VAPID لا تضيف صوتًا.
- سجل الحملات القديم الموجود في Firestore لم يُستورد إلى Supabase بحسب حالة الوثائق والكود المتاحة.

## 8. بقايا وملاحظات تحتاج تسوية

1. لم أجد استيرادًا نشطًا لـFirebase Auth أو Firestore في واجهات الاستخدام الحالية، لكن ما زالت ملفات مساعدة قديمة في المستودع: `server/data/firestoreQueries.ts` و`src/data/firestoreQueries.ts`، كما أن `server/firebaseAdmin.ts` يحتفظ بدالة `adminServices()` التي تهيئ Firestore. لم يظهر استدعاء لهذه الدالة من مسارات التطبيق النشطة؛ استخدامها الظاهر في الاختبارات/البنية المساعدة. تزال لاحقًا بعد مراجعة الاختبارات واعتمادات النشر.
2. `docs/architecture/SUPABASE_MIGRATION.ar.md` وثيقة مرحلة سابقة وتقول إن Firebase ما زال مصدر الإنتاج. وبعض أقسام `docs/AUTHENTICATION_SUPABASE_AND_NOTIFICATIONS_MAP_2026.ar.md` تذكر أن Push الويب لم يكتمل. يلزم تحديثهما ليتوافقا مع وضع 7 نوفمبر؛ وثيقة `docs/NOTIFICATIONS_AND_PROMOTIONS_PLAN.ar.md` أحدث في وصف PWA.
3. لا يمكن وصف نقل Firebase التاريخي بأنه مكتمل دون سجل تصدير/استيراد ومطابقة أعداد ومراجعة استثناءات. أعداد الجداول الحالية ليست دليلًا كافيًا لذلك.
4. ينبغي تفعيل الإشعارات على هاتف حقيقي ثم إرسال حملة «جهازي للاختبار» والتحقق من المقدمة والخلفية والنقر. بعده يمكن تقييم متطلبات نغمة Flutter الأصلية إن كانت مطلوبة.
5. لم تُدرج أي أسرار في التقرير. أي مفاتيح إدارة سرية سبق إرسالها في المحادثة يجب تدويرها بعد انتهاء التحقق؛ مفتاح VAPID عام وليس مفتاح إدارة سريًا.
