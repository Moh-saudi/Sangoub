# تفعيل التشغيل الحقيقي لطلبات العاصمة

## ما وجده الفحص

تم تحديث إعدادات تطبيق Web إلى مشروعكم `capital-talabat` بالبيانات التي قدمتموها، واستخدام قاعدة `(default)` في العميل والخادم وملف نشر القواعد. إعدادات الويب العامة، بما فيها measurementId، محفوظة في `firebase-applet-config.json`، والمشروع الافتراضي لأداة Firebase CLI مضبوط في `.firebaserc`.

لم يتوفر تسجيل دخول إداري إلى Firebase CLI في بيئة العمل؛ محاولة قراءة تطبيقات المشروع أعادت «Failed to authenticate». إعدادات Web ليست مفتاح حساب خدمة ولا تمنح صلاحية إدارة Firebase. لذلك لم تُنشأ قاعدة حية، ولم يُفعّل أي موفر مصادقة ولم تُنشر قواعد أو صلاحيات مدير على السحابة. بيانات ADC المتاحة سابقًا لا تخص هذا المشروع.
قبل التحديث كانت الحسابات والطلبات والإشعارات والمتاجر تجريبية، وبعض الإجراءات تحفظ في ذاكرة المتصفح فقط. فشل كتابة الطلب لم يكن يمنع ظهور نجاحه. تسجيل Google كان يرجع لحسابات مصطنعة عند الخطأ، والمحفظة والبطاقات كانت محاكاة. أُزيلت هذه المسارات من التشغيل الفعلي.

## 1. اختر مشروع Firebase تملكه

افتح https://console.firebase.google.com/project/capital-talabat بحساب الشركة. اختير مشروع `capital-talabat` من إعدادات Web التي قدمتموها؛ راجع وجود تطبيق Web ذي App ID الذي ينتهي بـ `e9e837`. أنشئ Firestore في وضع الإنتاج إذا لم تنشئه بعد، واستخدم قاعدة `(default)`. يجب أن يشير العميل والخادم ونشر القواعد إلى القاعدة نفسها.

القيم الافتراضية في المستودع أصبحت تخص هذا المشروع. إذا كانت Vercel تحتوي متغيرات `VITE_FIREBASE_*` أو `FIREBASE_*` قديمة فإنها تتغلب على هذه القيم؛ حدّثها أو احذف القديم منها ثم أعد النشر. اختر منطقة قاعدة البيانات بعناية قبل إنشائها.

## 2. فعّل المصادقة

من Authentication → Sign-in method:

- Google: فعّله واختر بريد الدعم الخاص بالشركة. الاختيار الفعلي للحساب يتم في نافذة Google، ولا توجد قائمة حسابات وهمية.
- Email/Password: فعّله. التطبيق ينشئ الحساب ويرسل رسالة تأكيد البريد؛ لا يسمح بالطلبات قبل التحقق. استعادة كلمة المرور تعمل من رسالة Firebase.
- Phone: فعّله إن أردت SMS، وراجع متطلبات الفوترة وحصص SMS وسياسة المناطق، وأضف مصر ضمن المناطق المسموح لها. التطبيق يستخدم reCAPTCHA وSMS ثم يتحقق من الرمز. استخدم أرقام اختبار Firebase في مرحلة التجربة لتجنب الرسوم، ولا تفعّل تعطيل reCAPTCHA في الإنتاج.

من Authentication → Settings → Authorized domains أضف `capital-talabat.vercel.app` وأي نطاق رسمي مخصص. للنشر التجريبي استخدم نطاق Preview محددًا عند الحاجة. إذا قُيّد مفتاح الويب بـ HTTP referrers في Google Cloud، أضف النطاقات نفسها إلى القيود. لا تُزل قيود المفاتيح لتجاوز المشكلة. راجع قوالب رسائل التأكيد واستعادة كلمة المرور وبريد الدعم.

هذه الخطوات تتطلب الدخول لحساب Firebase؛ رفع الكود وحده لا يفعّل موفري المصادقة.

## 3. متغيرات Vercel

في Project → Settings → Environment Variables أدخل القيم بأمان، وفعّلها لبيئة Production. بعد تعديل متغيرات `VITE_*` أعد النشر لأنها تُضمَّن أثناء البناء.

| الاسم | مكانه والغرض منه |
| --- | --- |
| `VITE_FIREBASE_API_KEY` | مفتاح تطبيق Web العام من إعدادات مشروعكم |
| `VITE_FIREBASE_PROJECT_ID` | معرّف المشروع |
| `VITE_FIREBASE_AUTH_DOMAIN` | نطاق المصادقة من Firebase |
| `VITE_FIREBASE_APP_ID` | معرّف تطبيق Web |
| `VITE_FIREBASE_DATABASE_ID` | `(default)` أو اسم القاعدة الفعلي |
| `FIREBASE_PROJECT_ID` | نفس المشروع، للخادم |
| `FIREBASE_DATABASE_ID` | نفس القاعدة، للخادم |
| `FIREBASE_CLIENT_EMAIL` | بريد حساب خدمة ينتمي لهذا المشروع |
| `FIREBASE_PRIVATE_KEY` | المفتاح الخاص لحساب الخدمة؛ متغير خادمي سري فقط، دون بادئة VITE |
| `GEMINI_API_KEY` | اختياري لتفعيل المساعد والصوت، متغير خادمي سري |
| `GEMINI_MODEL` | اختياري، اسم نموذج متاح لحسابكم؛ الافتراضي `gemini-2.5-flash` |

أنشئ حساب خدمة تابعًا للمشروع `capital-talabat` من Google Cloud IAM أو Project settings → Service accounts. استخدم أقل الصلاحيات اللازمة: الوصول إلى Firestore للقراءة والكتابة (`Cloud Datastore User`) وقراءة مستخدمي Firebase Authentication للتحقق من إبطال الجلسة (`Firebase Authentication Viewer`). لا ترفع JSON أو المفتاح إلى GitHub. يدعم الخادم أسطر PEM الفعلية أو `\n` داخل المتغير. هذا المفتاح يستخدم للتوقيع المحلي على الخادم؛ لا تستبدله بمتغير proxy placeholder. بعد تدوير المفتاح، أعد نشر وظائف Vercel.

للتشغيل المحلي: `npm run dev`. لفحص الناتج الإنتاجي محليًا بعد البناء: `NODE_ENV=production npm start`.

إعداد البناء: Vite، `npm run build`، الناتج `dist`. المستودع يحتوي `vercel.json`، ووظيفة `/api/orders` ووظائف `/api/gemini/{chat,maps,transcribe}`. واجهة Vite وحدها دون هذه الوظائف لا تكفي لاستقبال الطلبات. تأكد أن Production branch هو `main` وأن مجلد الجذر هو جذر هذا المشروع.

## 4. نشر قواعد Firestore

راجع القواعد واختبرها قبل النشر. استخدام Test mode أو `allow read, write: if true` ليس تفعيلًا صالحًا للإنتاج.

الإعداد `firebase.json` يستهدف قاعدة `(default)` في مشروع `capital-talabat` المضبوط في `.firebaserc`. ملف `firebase.emulators.json` مخصص للاختبارات المحلية فقط. ثم من جهاز لديه صلاحيات مشروعكم:

```bash
npx firebase login
npx firebase deploy --only firestore --project capital-talabat
```

لا تنشر هذه القواعد تلقائيًا على مشروع لم تتأكد من امتلاكه. قواعد النسخة الجديدة تمنع إنشاء الطلبات مباشرة من المتصفح؛ إنشاؤها يتم عبر وظيفة `/api/orders` الموثقة فقط. لذلك جهّز مفاتيح الخادم ووظائف Vercel والقواعد كعملية تفعيل واحدة، وأوقف استقبال طلبات حقيقية أثناء النقل من النسخة القديمة.

القواعد تعزل طلبات العميل، ومدير المطعم حسب `storeIds`، والمندوب حسب `courierId`. حقول الدور في ملف المستخدم وlocalStorage لا تمنح أي صلاحيات. القواعد تمنع تعديل الأسعار الإجمالية والمالك وحالة الدفع بصورة غير مشروعة، وتمنع إعادة فتح طلب نهائي. لا تُمنح الإدارة بناء على بريد مكتوب داخل الكود.

## 5. تفعيل المدير الرئيسي

1. سجّل حسابًا حقيقيًا باستخدام Google أو البريد المؤكد أو الهاتف.
2. انسخ UID من Authentication → Users. يمكن أيضًا رؤيته في صفحة «حسابي» بعد الاتصال بقاعدة البيانات.
3. من Firestore Console، في القاعدة المختارة، أنشئ Collection باسم `admins` ووثيقة اسمها UID نفسه. يمكن إضافة الحقل `enabled: true` للتوضيح؛ وجود الوثيقة هو الذي يمنح الصلاحية، وحذفها يلغيها. `enabled: false` لا يعطل الحساب؛ احذف الوثيقة لإلغاء الإدارة.
4. سجّل الخروج والدخول مجددًا، ثم افتح `/admin`. مثال: `https://capital-talabat.vercel.app/admin` بعد اكتمال نشر التحديث.

لا يوجد الآن بريد أو كلمة مرور افتراضيان للمدير، ولا يستطيع المستخدم إضافة نفسه إلى `admins`. إنشاء هذه الوثيقة أول مرة يتم من حساب مسؤول Firebase فقط. لا يمكنني تحديد مدير لكم دون حساب حقيقي وملكية مؤكدة للمشروع.

## 6. إعداد المطاعم والمنيو والمناديب

من لوحة التحكم افتح «إعداد المتاجر والأصناف وفريق التشغيل»:

- أضف المتاجر بعناوينها ورسوم التوصيل والحد الأدنى الحقيقي.
- أضف الأصناف والصور والأسعار. المتاجر والأصناف الفارغة لن تُستبدل ببيانات تجريبية تلقائيًا.
- اطلب من المندوب ومدير المطعم تسجيل حساب حقيقي. أضف UID والاسم والهاتف والدور، وحدد المتجر لمدير المطعم. يعيدان تسجيل الدخول لاستلام الصلاحية.
- أضف أكواد الخصم الفعلية عند الحاجة. لا توجد قسائم تلقائية أو رصيد محفظة وهمي.

يمكن للمدير استقبال الطلبات ومراجعتها وتغيير حالتها، وتعيين مندوب حقيقي، وإدارة المخزون والأسعار والمتاجر وطلبات الشراكة والتوظيف. بيانات طلبات الشراكة والتوظيف لا يقرأها إلا المدير؛ إرسال الطلب يحتاج حسابًا موثقًا.

## 7. دورة الطلب الحقيقية

العميل يسجل الدخول، يضيف الأصناف، يحفظ الوزارة والدور والمكتب وGPS إن أراد، ثم يؤكد السلة. لا تظهر رسالة نجاح إلا بعد حفظ الطلب على الخادم. عند الفشل تبقى السلة ويظهر الخطأ.

الخادم يتحقق من Firebase ID token وحالة تأكيد الحساب، ويقرأ أسعار المنتجات والخيارات ورسوم المتاجر والخصومات من Firestore، ويرفض المخزون النافد والمتجر المغلق والكميات والخيارات غير الصالحة. لا يثق بالأسعار أو الدور أو حالة الدفع المقدمة من المتصفح. تكرار محاولة الإرسال بنفس معرف الطلب لا ينشئ نسخة ثانية. الحد الحالي ٣٠ طلبًا لكل حساب خلال ٢٤ ساعة.

السجلات القديمة التي كانت تحفظ ملخص الأصناف فقط لا تُحذف؛ تعرض بعلامة «سجل قديم». تفاصيل الأصناف والأسعار الفرعية المفقودة لا يمكن استعادتها من الملخص. لم تُنفّذ هجرة أو حذف لأي بيانات حية.

طلبات جديدة وتغييراتها تصل عبر `onSnapshot` إلى العملاء المسموح لهم. يبدأ المطعم التحضير ويؤشر جاهزية الاستلام. المدير يعيّن المندوب. المندوب يشير إلى الاستلام والوصول والتحصيل ثم يغلق الطلب. الطلب المُسلّم أو الملغى لا يمكن إعادة فتحه بالقواعد الحالية.

**الدفع الإلكتروني والمحفظة غير مفعّلين.** المسار الحالي نقد عند الاستلام فقط. لا يطلب الموقع رقم بطاقة أو CVV، ولا يحوّل إلى عنوان InstaPay تجريبي. تفعيل بوابة دفع حقيقية يحتاج حساب تاجر وعقدًا ومفاتيح خادم وwebhook متحققًا من التوقيع؛ لا يتم اعتبار الطلب مدفوعًا بمجرد الضغط على زر. لا توجد خدمة FCM لإرسال إشعارات عندما تكون الصفحة مغلقة؛ التحديثات المباشرة داخل الصفحة فقط.

## 8. الخريطة الحقيقية

تحديد GPS يعمل عبر صلاحية الموقع في المتصفح وعلى HTTPS. يمكن إدخال الإحداثيات يدويًا بعد نسخها من Google Maps. تظهر معاينة OpenStreetMap وروابط Google Maps للبحث والاتجاهات؛ هذه الوظائف لا تحتاج مفتاح Google Maps مدفوعًا. دقة GPS تعتمد على الجهاز، ولا تحدد الطابق أو المكتب، لذلك تظل بيانات العنوان مطلوبة.

المندوب المعيّن يمكنه مشاركة موقعه أثناء فتح صفحة الطلب وبموافقته، بمعدل لا يتجاوز تحديثًا كل عشر ثوانٍ. يسمح للعميل والمدير والمطعم المعني بقراءة آخر موقع. الوقت الأخير ظاهر، والموقع القديم لا يوصف بأنه مباشر. تتوقف المشاهدة عند إغلاق الصفحة؛ هذا ليس تتبعًا في خلفية الهاتف أو تطبيق ملاحة. Firestore يحتفظ بآخر إحداثيات، ويفضل ضبط سياسة احتفاظ ببيانات التتبع حسب سياسة الخصوصية.

بحث عنوان الوزارة يفتح Google Maps مباشرة. استنتاجات المساعد الذكي عن الأماكن لا تستبدل GPS أو نقطة التوصيل، وتعتمد على إتاحة نموذج Gemini لخدمة Maps grounding. المساعد اختياري ومحدود إلى ٢٠ طلبًا للحساب في الساعة ويتطلب مصادقة؛ فشله لا يمنع الطلب النقدي أو الخريطة.

## 9. الفحوص قبل استقبال عملاء

```bash
npm run lint
npm test
npm run build
npm run test:auth
npm run test:rules
```

يتطلب المحاكي Java 21 وتنزيلًا موثوقًا من `storage.googleapis.com`. اختبارات المحاكي تستخدم مشروع `demo-capital-talabat` المعزول، ولا تستخدم بيانات الإنتاج. للتخزين داخل هذه البيئة المقيدة أضف قبل أمر الاختبار: `FIREBASE_EMULATORS_PATH=/workspace/.firebase-emulators XDG_CONFIG_HOME=/workspace/.config`.

فحص تشغيل فعلي بحسابات منفصلة على متصفحين/أجهزة مختلفة:

1. Google والبريد وتأكيده وإعادة تعيين كلمة المرور والهاتف/reCAPTCHA/SMS، حسب الموفرين الذين فعلتهم.
2. العميل العادي لا يرى لوحة الإدارة أو طلبات الآخرين حتى بعد التلاعب بالمتصفح.
3. إنشاء متجر وصنف من المدير، ظهورهما في جهاز العميل، تغيير السعر/المخزون واستمراره بعد التحديث.
4. إرسال طلب نقدي ومراجعة سعره وتفاصيله وإحداثياته في جهاز المدير ثم المطعم.
5. تعيين مندوب ومشاركة GPS وتتبع آخر تحديث ثم إتمام التسليم والتحصيل. لا يراه مندوب آخر.
6. قطع الشبكة قبل الإرسال: لا يظهر نجاح ولا تضيع السلة. إعادة المحاولة لا تنشئ طلبًا مكررًا.
7. إرسال طلب شراكة/توظيف: يظهر للمدير بعد تحديث صفحة أخرى، ولا يقرؤه عميل آخر.

لا تعتبر التشغيل جاهزًا للإنتاج قبل نجاح اختبارات القواعد والتجربة الحقيقية على مشروعكم. خلال هذا العمل نجح البناء وTypeScript و١١ اختبارًا للحسابات و٤ اختبارات مصادقة على محاكي Auth وفحص الواجهات وGPS في المتصفح. لم تعمل اختبارات Firestore بسبب حجب تنزيل محاكيه، ولم يُختبر تسجيل الدخول أو الطلبات على Firebase/Vercel الحيّين، ولم تُنشر القواعد أو تُنشأ أي صلاحيات إدارية على السحابة.
