## قراءات راجعتُها ولا تعتبر تكرارًا زائدًا

- اشتراكات الإدارة الأساسية مركزية داخل `AdminApp`، وتشارك الشاشات بياناتها عبر الخصائص.
- الرئيسية والعروض تستخدمان مسارين منفصلين؛ اشتراكات الكتالوج فيهما ليست متزامنة عند التنقل، ولهما نطاقا بيانات مختلفان.
- إعادة قراءة صلاحية المدير وقفل الحساب داخل معاملة الكتابة مقصودة لمنع سباق سحب الصلاحية، وليست قراءة يمكن حذفها بأمان.
- تكرار قراءة طلب محفوظ للتحقق من البصمة مطلوب لضمان عدم إنشاء طلبين عند فقد الاستجابة.

## نقاط تحتاج عملًا لاحقًا عند توسيع النظام

- اشتراك `subscribeToOrders` للإدارة يقرأ كامل سجل الطلبات، والمنتجات والمتاجر في الإدارة أيضًا تُقرأ كقوائم كاملة. يلزم فصل الطلبات النشطة عن تاريخ مقسم بصفحات، مع إبقاء التقارير صحيحة؛ وضع حد عشوائي الآن سيُسقط بيانات من مؤشرات التشغيل والتقارير.
- `PublicOffers` يقسّم النتائج في الواجهة بعد قراءة كل المنتجات المتاحة؛ التقسيم الحالي لا يقلل قراءات Firestore. يلزم مسار تصفية وترتيب وصفحات على الخادم قبل تغيير ذلك.
- خريطة المناديب تستخدم استعلامًا واسعًا على `tracking`، بينما عقد الوصول الحالي يحتاج مراجعة إدارية مخصصة. الأفضل مسار إدارة يعيد مواقع الطلبات النشطة المطلوبة فقط، بدل توسيع قواعد الوصول أو قراءة المجموعة كاملة.
- لم أُعد كتابة شاشات الويب القديمة أو كود الموبايل ضمن هذه المهمة؛ تغيير تلك المسارات يحتاج تحققًا مستقلًا من استخدامها.
