# الاستضافة والتخزين وتشخيص نسخ الموقع

هذه خدمات منفصلة في الإعداد الحالي للمستودع:

- **الموقع وواجهات `/api`**: إعداد `vercel.json` ووظائف Node.js 24. لا يوجد إعداد Firebase Hosting في المشروع، ولا يوجد Worker/Pages Function لنشر هذه الواجهات على Cloudflare في النسخة الحالية.
- **صور المتاجر والمنتجات**: Cloudflare R2، حاوية `capitaltalabat`. بقي رفع الصور إلى R2 ولم يُنقل إلى Firebase Storage.
- **الحسابات والبيانات والصلاحيات**: Firebase Authentication وFirestore في `capital-talabat`. أمر `firebase deploy --only firestore` ينشر قواعد الوصول والفهارس، ولا يرفع صورًا أو موقعًا إلى Firebase Hosting.

مفاتيح R2 (`R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` أو بدائل `CLOUDFLARE_R2_*`) لا تمنح إدارة حسابات Firebase. واجهات الإدارة تحتاج اعتماد الخادم `FIREBASE_CLIENT_EMAIL` و`FIREBASE_PRIVATE_KEY`، إضافة لمعرّف المشروع. مفاتيح `VITE_FIREBASE_*` هي إعدادات تطبيق العميل وليست اعتماد Firebase Admin. لا تُنشر المفاتيح الخاصة مع ملفات الواجهة.

إذا كانت هناك استضافة Cloudflare Pages أو Workers خارج هذا المستودع، يجب تحديد رابطها وإعداد وظائفها الفعلية. رفع `dist` وحده إلى خدمة ملفات ثابتة لا يشغّل وظائف Node الموجودة تحت `/api`. ملفات `_headers` المرفقة تضبط التخزين المؤقت عند استخدام Pages للملفات الثابتة، ولا تنشئ خادم API.

## خطأ تشغيل وظائف الإدارة

ملفات `api/*.ts` هي نقاط دخول خفيفة، وتحمّل التنفيذ الموجود في `server/handlers/*.ts`. فشل تحميل SDK أو التنفيذ يُعاد كاستجابة JSON برمز ومعرّف حادثة ويُكتب في Runtime Logs، بدل إخفائه بانهيار غير مُشخّص. لا تُعرض رسائل الاستثناء الداخلية أو المفاتيح للمتصفح. المكتبات الحالية تتطلب Node حديثًا؛ `engines.node=24.x` يطابق بيئة الاختبار.

- طلب بلا جلسة إلى واجهة الإدارة: `401` متوقع.
- `FIREBASE_ADMIN_NOT_CONFIGURED`: لم تُضبط متغيرات اعتماد Firebase Admin في خادم الاستضافة.
- `FIREBASE_ADMIN_INVALID_CREDENTIALS`: اعتماد الخادم غير صالح؛ راجع ضبطه داخل الاستضافة.
- `SERVER_MODULE_LOAD_FAILED`: راجع Runtime Logs بمعرّف الحادثة لمعرفة المكتبة أو الملف الذي تعذر تحميله.
- `FUNCTION_INVOCATION_FAILED` عام من منصة الاستضافة: الوظيفة لم تصل لنقطة الدخول أو النسخة المنشورة أقدم؛ راجع إصدار النشر والسجلات.

وجود مفاتيح محفوظة في حساب استضافة خارجي لا يجعلها تلقائيًا متاحة لجلسة التطوير أو لمنصة أخرى.

## التصميم القديم والتخزين المؤقت

يُصدر كل بناء `build-info.json` بمعرّف commit وتوقيت البناء. يظهر معرّف النسخة المختصر في تذييل الإدارة. تقارن اللوحة نسختها بالنسخة المنشورة وتعرض زر تحميل النسخة الجديدة بعد حفظ التعديلات. لا تُحذف جلسات Firebase أو بيانات المتصفح ولا يُفرض تحديث أثناء تحرير نموذج.

عند الانتقال لأول مرة من إصدار قديم لا يحتوي تنبيه التحديث، استخدم `Ctrl+Shift+R` على الكمبيوتر. إذا ظلت النسخة القديمة، افتح أدوات المطور > Application > Service Workers > Unregister ثم أعد التحميل. لا تحتاج مسح كلمات المرور أو مفاتيح الموقع. ملفات الخدمة والنسخة وHTML لها ترويسات إعادة التحقق من التخزين المؤقت.

## الفحص

`npm run test:compiled-api` يختبر JavaScript الناتج من التجميع ويحمل التنفيذ الفعلي لكل وظيفة، إضافة إلى `test:native-api` واختبارات المحاكيات. اختبار المصادقة يشغّل Auth وFirestore معًا لأن فحص إلغاء الجلسات يحتاج `accountAccess`. اختبار PWA يتحقق من تنشيط ملف الخدمة وظهور تنبيه النسخة الأحدث.
