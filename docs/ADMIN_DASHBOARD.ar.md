# تشغيل لوحة الإدارة

الواجهة الجديدة في `feature/real-orders-auth-maps` وتفتح من `/admin`؛ الصفحة `/` موقع تعريفي عام للعملاء والشركاء. بوابة الإدارة مستقلة دون محاكي أو حسابات تشغيل موبايل. تستخدم Firebase Authentication وFirestore، ولا تنشئ حساب مدير أو منتجات وأسعارًا افتراضية. يجب أن يكون للحساب الحقيقي وثيقة `admins/<Firebase UID>` أضافها مسؤول المشروع. القواعد المنشورة تتحقق من الوثيقة؛ حفظ `role: admin` في المتصفح لا يمنح صلاحية.

## المنتجات والمتاجر

1. افتح «المنتجات والمتاجر» ثم «المتاجر» → «إضافة متجر». أدخل الاسم والنشاط والتصنيف والعنوان ورسوم التوصيل والحد الأدنى. المتجر الجديد مغلق افتراضيًا حتى تختار فتحه.
2. افتح «المنتجات» → «إضافة منتج». اختر متجره وأدخل الاسم والوصف والسعر والتصنيف، ثم ارفع صورته أو أدخل رابط HTTPS لصور تملكون حق استخدامها. يمكن إضافة السعر قبل الخصم والشارة وإظهاره ضمن المنتجات المميزة.
3. «تعديل» يفتح بيانات المنتج الحالية لتعديلها وصورته. يبقى المتجر ثابتًا للصنف الموجود، وتُحفظ خياراته السابقة التي لا يعدلها النموذج. السعر قبل الخصم الفارغ يعني عدم وجود خصم معلن؛ يجب ألا يقل عن سعر البيع.
4. التوافر يمكن إيقافه وتفعيله. «أرشفة» تخفي الصنف من المنيو وتمنع إنشاء طلبات جديدة له، دون حذف تفاصيل طلباته السابقة. «استعادة» تعيده غير متاح؛ فعّله عندما يصبح جاهزًا للبيع.
5. ابحث بالاسم أو المتجر أو الوصف، وصفِّ بالمتجر والتصنيف والتوافر، ورتّب بالاسم أو السعر أو الكميات المسلّمة.

لكل صنف كميات مسلّمة وقيد التنفيذ، وقيمة أصنافه المسلّمة حسب لقطة السعر عند الطلب، بما فيها الإضافات وقبل خصم القسائم ورسوم التوصيل. لا تُحسب الطلبات الملغاة. البيانات مبنية على سجلات الطلبات المتاحة، ولا تُستنتج أصناف من ملخص قديم مفقود التفاصيل. هذا ليس نظام مخزون كمي؛ `inStock` توافر يدوي ولا يمثل رصيد قطع.

رفع الملفات الفعلي يحتاج إعداد R2 والخادم الموثق في [R2.ar.md](R2.ar.md). تعديل النصوص والأسعار أو استخدام رابط صورة قائم يتم عبر Firestore من جلسة مدير، دون المرور بخدمة رفع الملفات. لا تُرسل مفاتيح R2 إلى المتصفح.

## الفريق والخصومات

- من «الفريق والخصومات» أضف UID لحساب حقيقي مسجل، وحدد دور المندوب أو مدير المتجر، وبياناته والمتجر المسؤول عنه. يمكن تعديل السجل من القائمة أو إلغاء صلاحية الموظف. لا يتم حذف حساب Firebase Authentication أو طلباته. واجهة الإلغاء تمنع سحب صلاحية مندوب له طلبات نشطة قبل إعادة تعيينها.
- أضف كود خصم ثابت بالجنيه أو نسبة حتى 100%، وحدًا أدنى للطلب ووصفًا. القائمة تدعم تعديل الكود الحالي أو حذفه؛ معرف الكود ثابت أثناء التعديل. حذف الكود لا يغيّر إجماليات الطلبات السابقة.
- إنشاء المدير الرئيسي ما زال من حساب مسؤول Firebase فقط. لا توجد كلمة مرور أو شخصية مدير افتراضية.

## الطلبات والمطبخ والعمليات

«الطلبات والتقديمات» تعرض الطلبات وطلبات الشراكة والتوظيف. يمكن البحث برقم الطلب أو اسم العميل أو الهاتف، والتصفية بالوزارة والحالة بما فيها الملغاة. يُعين المدير مندوبًا لطلب جاهز أو يعيد تعيينه وهو في الطريق، ويمكن إلغاء طلب غير نهائي بعد تأكيد الإلغاء. الانتقالات تنتظر حفظ الخادم وتعرض الأخطاء. التسليم النهائي يتم بواسطة المندوب برمز العميل والتحصيل عبر API.

تستمر شاشة المطبخ والعمليات الحية الموضحة في [WEB_MOBILE_INTEGRATION.ar.md](WEB_MOBILE_INTEGRATION.ar.md). إحصاءات التسليم اليومية تستخدم توقيت القاهرة ووقت التسليم الموثق.

## التجربة المحلية

```bash
npm install
npm run dev
```

افتح `http://localhost:3000/admin` على الجهاز الذي شغّلت عليه المشروع. لإعداد خدمات الخادم الحقيقية، ضع الأسرار في `.env.local` داخل المشروع؛ الخادم يدعم تحميله محليًا، وملفات البيئة مستبعدة من Git. لا تحتاج إضافتها إلى Vercel لتجربتها على جهازك. اختبارات المحاكيات لا تحتاج مفاتيح إنتاج.

تجربة المتصفح المنفذة على مشروع `demo-capital-talabat` المعزول شملت إنشاء متجر وصنف، حفظ السعر ثم قراءته من Firestore، التوافر والأرشفة والاستعادة، البحث، حفظ الخصم، رفض الكتابة بعد سحب الإدارة، وأحجام 390/768/1440. الصور المرفوعة إلى حاوية R2 الحقيقية لم تُختبر لغياب إعداداتها السرية من بيئة الوكيل؛ لم تُضف منتجات أو بيانات اختبار إلى مشروع الإنتاج.


اختبار بوابة الإدارة الكامل: نفّذ `npx playwright install chromium` مرة واحدة ثم `npm run test:admin-web` مع Java 21. الاختبار يبدأ محاكيات Auth وFirestore ويختبر رفض الأدوار الثلاثة ودخول المدير والسحب الحي للصلاحية والحفظ من الواجهة. يستخدم مشروع demo معزولًا ويرفض العمل خارج المحاكيات المحلية. في هذه البيئة استخدم `CHROMIUM_PATH=/usr/bin/chromium` لاستعمال Chromium الموجود.


## تحديث تجربة الإدارة — ٢٢ أكتوبر ٢٠٢٦

- قائمة جانبية للأقسام على الكمبيوتر وقائمة قابلة للفتح والإغلاق على الموبايل، مع حفظ القسم المختار في رابط الصفحة.
- مركز العمليات يعرض يوم القاهرة والجهة والمؤشرات اليومية ومسار حالات الطلبات. اختيار حالة يعرض الطلبات النشطة من جميع الأيام، بينما العرض الافتراضي يعرض طلبات اليوم المختار.
- البحث يشمل رقم الطلب والعميل والهاتف والوزارة. تظهر أحدث ثمانية طلبات في الملخص، وتتوفر الإدارة الكاملة في قسم الطلبات والتقديمات.
- توزيع الجهات قابل للتوسيع، وحالات الفراغ تقود لإضافة المتجر والفريق. لا تظهر خرائط أو مواقع أو نسب إنجاز افتراضية.
- جميع المؤشرات والعدادات مصدرها الاشتراكات الحالية؛ تغييرات التصميم لا تمنح صلاحيات ولا تغيّر قواعد الأمان أو عقد Flutter.
