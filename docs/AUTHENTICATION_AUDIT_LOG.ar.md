## 2. جدول تدقيق الخطوات المنجزة بالكامل (Completed & Verified)

### أولاً: منظومة المصادقة والأدوار (Authentication & Role Verification)
- [x] **إلغاء أدوار المحاكاة الوهمية:** تم استبعاد أي اختيار يدوي للدور (Mock Roles) أو كلمات مرور تجريبية ثابتة داخل تطبيق Flutter.
- [x] **اعتماد جلسة Firebase Auth الرسمية:** الربط المباشر مع `FirebaseAuth.instance.currentUser` والتحقق من الـ UID الحقيقي.
- [x] **الفحص التراتبي للصلاحيات من Firestore:**
  1. فحص `admins/{uid}`: إذا وجد يُمنح صفة `UserRole.admin`.
  2. فحص `staff/{uid}`: قراءة الحقل `role` (`restaurant` أو `courier`) مع قراءة `storeId` المخصص للشيف.
  3. الافتراضي: `UserRole.employee` للعملاء والموظفين مع إنشاء وثيقة تلقائية متوافقة في `users/{uid}`.
- [x] **فصل لوحة تحكم الويب:** شاشات الويب لا تحتوي على محاكي موبايل أو أدوار تجريبية، ومحصورة على `admins/{uid}` بالتحقق الثنائي `isVerifiedIdentity`.

### ثانياً: الكتالوج الحي والمتاجر والوسائط (Catalog & Cloudflare R2)
- [x] **استماع حي لمجموعات Firestore الحقيقية:**
  - `stores`: قراءة المتاجر النشطة فقط (`status == 'open'`).
  - `products`: قراءة المنتجات المتاحة واستبعاد المؤرشفة (`archived == true`).
- [x] **محرك صور موحد وذكي (`AppImage`):**
  - دعم الروابط الخارجية لـ Cloudflare R2 وشبكة التوزيع CDN وروابط Firebase Storage.
  - دعم التخزين المؤقت المحلي (Caching) والرموز البديلة اللائقة في حال انقطاع الشبكة.

## 3. التدقيق الحالي لقواعد البيانات والصلاحيات (Database & Security Audit)

```
Firestore Security Map:
├── admins/{uid}           [قراءة: للمدير والمالك فقط | كتابة: مغلقة حصراً لوحدة التحكم]
├── staff/{uid}            [قراءة: للموظف والمدير | كتابة: للمدير فقط عبر لوحة الويب]
├── users/{uid}            [قراءة وكتابة: للموظف صاحب الحساب بمطابقة auth.uid]

├── products/{id}          [قراءة: للجميع | تعديل: للمدير أو شيف المتجر المرتبط]
├── coupons/{code}         [قراءة: للجميع | كتابة: للمدير فقط]
└── orders/{id}            [إنشاء: للسيرفر فقط | تعديل: للمدير والمندوب والشيف وفق الصلاحيات]
```
